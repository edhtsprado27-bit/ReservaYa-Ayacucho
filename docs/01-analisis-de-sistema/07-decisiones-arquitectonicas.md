# Decisiones arquitectónicas (ADR)

Registro de las decisiones de arquitectura. Cuando una decisión cambia, **no se borra**: se marca como *Reemplazada* y se agrega la nueva, con el motivo. Así queda la historia de por qué el sistema es como es.

| ID | Decisión arquitectónica | Driver relacionado | Justificación | Resultado en el código | Estado |
|---|---|---|---|---|---|
| ADR-001 | Monolito modular | DA06 – Mantenibilidad, DA08 – Equipo y costo | Una sola aplicación desplegable, dividida en módulos independientes; adecuada para un equipo pequeño. | `apps/web/src/modules/`: compartido, cuentas, catálogo, reservas y pagos. | Vigente |
| ADR-002 | Clean Architecture dentro de cada módulo | DA06 – Mantenibilidad | Separar las reglas del negocio de los detalles tecnológicos. | Carpetas `dominio/`, `aplicacion/`, `infraestructura/` y `presentacion/` en cada módulo; las rutas `app/api/` son la capa de presentación. | Vigente |

| ADR-009 | Next.js full-stack en Vercel (web + API REST en un solo despliegue), en lugar de una API NestJS en Render | DA08 – Equipo y costo, DA02 – Rendimiento | Un solo proyecto y un solo despliegue gratuito; el plan gratis de Render apaga el servidor y tarda en encender. Probado: 20 reservas simultáneas → 1 gana. | Vigente |
